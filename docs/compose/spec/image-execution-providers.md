## [S2] 设计

### 2.1 边界与默认选择

马良 core 只管理规范任务、能力匹配、请求冻结、结果校验与文件记录。实际生图留给宿主工具桥；Python Protocol 本身不能召唤宿主工具。

执行配置默认 preferred=codex-subscription，available 由具体会话决定。偏好不代表可用；不可用时返回明确阻塞或输出可移交执行包。不自动降级到 MiMo，不自动切 API 按次付费，不读取/复制/复用另一个客户端的 OAuth token 或 cookie。

用户界面两项明确为：

1. mimo-desktop：当前 MiMo Agent 调用原生 image_gen/image_edit，显式备选。
2. codex-subscription：在 MiMo Desktop 内通过本机 codex exec 调度已用 ChatGPT 登录的 Codex 图像工具，默认首选；不是要求用户搬到 Codex 会话手动执行，也不是用 MiMo 原生工具指定 GPT。

第一版直接实现已实测的本地 CLI 执行桥。MiMo/马良冻结任务、拉起受限 Codex 子进程，Codex 调用其实际暴露的图像工具，父进程接收报告并核验图片。文件执行包用于本地审计与参数传递，不再是必须人工移交的产品主路径。不要求整个项目开发更换 Agent，不扩大为通用远程 Agent 平台。

### 2.2 最小规范任务与能力检查

规范任务区分 text-generate、reference-generate、edit。字段包含：任务/attempt ID、完整 prompt、参数、源图与参考图有序列表（路径/哈希/职责）、设计包哈希、所需输出及现有验收清单。

能力快照记录宿主及可核实版本、实际工具名、三种操作的支持情况、多图输入及已知数量限制、尺寸/输出格式/透明背景支持，值为 supported/unsupported/unknown。未知视为未具备必需能力；不瞎填上限。模型、授权类型和计费证据与工具名分开；不能将 image_gen 字符串当实际模型名。

MiMo 映射：text-generate→当前 image_gen；reference-generate/edit→当前 image_edit，真实图片参数必须进入工具调用。其他参数只按当时工具 schema 映射，不虚构 background 等不支持参数。不能传参考的操作在调用前拒绝，不把路径嵌到文字里冒充图像输入。

Codex 映射：调用前核对版本、脱敏登录状态和当前会话工具能力，不读凭证文件。已实测入口 tools.image_gen__imagegen 使用 prompt 与 referenced_image_paths；不假定名称永远不变。尺寸、quality、output_format 的显式选择在本次工具报告中不支持：必需要求则阻断，偏好要求可在用户已接受默认设置后省略并记录，不伪造参数。

首次游隼探测因子进程读取 JSON 被策略拒绝且零生图调用；随后父 Agent 将已读取原文与图片路径直接随任务传递，图像工具接收路径成功。桥应使用参数数组/标准输入传递完整任务，避免 shell 字符串拼接；不要求子进程先用 shell 读取父项目文件，不放宽 sandbox 或绕过权限。图片访问被拒则明确失败。

每任务一个新 attempt，仅允许一次图像调用，不自动重试。子进程超时但未确认图像调用是否完成时标记 execution-unknown，保留会话标识与日志，先核验已有结果再考虑新调用。输出可位于 Codex 默认 generated_images 目录；父进程仅接收预期目录内的普通可解码图片，核验路径/哈希，再不可覆盖地收录项目，不扫描无关文件。

### 2.3 请求与执行证据

流程：规范任务→能力匹配→工具参数映射→冻结实际调用参数→宿主执行→观察到的调用结果→交付校验。

冻结对象同时记录规范任务与映射后的实际调用参数、输入文件哈希。实际调用必须用这些参数，不允许 Agent 改写短 prompt 后复制旧 invocation 制造匹配回执。编辑把父图放在声明的位置，并明确风格参考职责。

完成记录至少包含 request ID/摘要、宿主/工具、实际参数摘要、输入图清单哈希/顺序、输出路径/哈希、成功或失败及证据来源。程序可采集的值由桥自动生成；若宿主无法提供机器日志，只能标注 host-agent-attested，不得标为 tool-observed。证据强度不同不能被一个 imageInputsVerified=true 取代。

结果不匹配时保留异常产物与 mismatch 记录，不绑定为原请求的合格交付，不自动重试扣费。调用重试/编辑创建新 attempt。已有 ProductionStore adoption 的艺术/技术门禁继续生效，provider成功不等于资产可采用。

### 2.4 诚实修复历史

V03 原文件和不可变事件保留；添加关联原事件/回执哈希的更正记录，说明实际未传参考且提示不一致，该回执不可作为参考图执行证据。禁止改写旧 receipt 假装从未错误。

V04 保留实际双图编辑事实；作为独立探索记录或诚实导入收编，不补造过去 prepared/request 时刻。用户认可的范围是普通单位/试作外形；技术验收与羽色科学核查独立保持未完成。不为本次需求新增全局 paletteStatus 字段；沿用检查项及证据表达。

### 2.5 文件交接与隐私

包内使用相对路径，包含任务、所需参考、输入哈希清单、执行说明和返回记录约定。项目授权的图片只保存在 art-pilot/本机交接目录，不进入马良公开examples/tests，也不自动云同步或上传。

交接包不含订阅凭证、API key、用户私有配置。接收端先校验哈希和工具能力，再执行；返回端核验请求绑定和产物，不信任自由文本“已完成”。

### 2.6 范围与验证方式

先小切口：两个执行路径能力定义、统一任务映射与校验、MiMo内本地Codex CLI桥、MiMo原生工具执行记录。既有两次Codex产图是入口验证证据，不替代新桥实现后的回归与一次授权端到端验证。

不引入第三provider、自动网页登录、非公开订阅接口、LoRA、通用远程Agent调度。保留既有ports.GenerationProvider；新增具体实现只用于确有执行能力的桥，无需重写authoring/geometry/state-machine。

验证包括离线假后端覆盖缺能力、图像丢失/乱序、prompt变更、输出哈希不符、失败/重试、新attempt。真实宿主烟测与离线测试分开。Codex环境缺失则工具开发可部分完成，但Codex真实路径仍blocked，不宣称两个provider全部交付。

### 2.7 实际测试用例：凤头鹰 Idle

用例 ID：crested-goshawk-idle-01。本轮添加设计与验收，不代表已执行图像调用。验证同一胶囊画风可迁移到不同物种，并且风格参考与物种参考能够独立绑定、实际提交；不是将游隼换色后冒称新物种。

- 项目范围：art-pilot 私有本机试点；不将照片或生成图写入马良公开 fixtures。用户附件 Created_goshawk_.jpg 为物种参考，版权/再分发许可未确认，不自动公开。实际执行前须定位附件本机文件并绑定 SHA-256，未定位不得伪造路径或声称已传图。
- 预期表现：沿用游隼试作的连续胶囊身体、粗深色轮廓、少量硬边平涂，单体地面收翼 Idle，双足完整可见。头脸可自然朝左；面朝方向与既有 DR 逻辑映射分别记录，不将喙朝左直接当成 UL 背视。无装备、场景或额外人设。
- 参考职责：输入1为后续确认的旧角色/已认可游隼风格图，只借画法、胶囊语言与静立构图，禁止复制游隼颊纹及物种身份；输入2为用户凤头鹰照片，只借可见身份特征与色块关系，禁止复制树叶、枝条、摄影光影、写实羽毛密度和细长真实身体比例。按任务 reference-generate 执行，即使宿主实际使用编辑工具，也不能误标为保留游隼身份的局部编辑。
- 照片可见特征：向后突出的短羽冠，灰色头颈与灰褐背翼，醒目的黄橙色虹膜和暗色瞳孔，小而弯钩的深色喙及黄蜡膜，浅色胸腹上的棕褐横斑，黄色足，以及带明暗横带的尾。尾部按胶囊风格缩短，但尽量保留可辨横带，不照搬照片长尾占用。
- 小图优先级：胶囊猛禽轮廓→羽冠与黄橙眼→胸腹横斑；将横斑简化为少量大条块，不增加细密纹理。不要加入游隼式大黑颊纹，不画成鸽子、鹦鹉或公鸡高冠。
- 执行路径：默认 MiMo 调度 ChatGPT 登录的 Codex 图像工具，先冻结完整提示和两图哈希/顺序，每次一个候选；MiMo 原生仅显式选择，不自动做双provider对比。
- 机审：输入职责/顺序/哈希、实际输出文件解码与尺寸、attempt隔离及请求一致性；透明与目标输出规格属于后处理门禁，不因原图有键色背景就宣称已通过。
- 人审：胶囊风格是否成立、是否有区别于游隼的凤头鹰特征、是否无枝叶/写实比例污染；展示原图、128/150预览及游隼/旧角色并排，附完整路径。首次视觉探索不要求用户先提供model sheet，不用椭圆调试图作为必需输入。
- 判定：美术认可、工具链通过和正式采用分别记录；羽冠/眼/横斑不能辨认或只是游隼改色时记录具体否决原因，不自动再抽；尚未执行则保持pending。
