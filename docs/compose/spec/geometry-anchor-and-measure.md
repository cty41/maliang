## [S1] 问题与已确认原则

本规格在原路径替换旧“只补锚图和 alpha bbox”方案，作为唯一当前方案。它记录当时的目标行为；当前已提交范围和仍待视觉验收范围以上方 Report 为准。

当前马良提供记录、Review、姿态证明和状态机；art-pilot 曾以纯文字生成游隼，缺少实际视觉参考。后续确定性渲染器把所有部件都画为椭圆，DR/UL 只改变中央三角方向标记；得到的是布局占位图，不是游隼设计、有效剪影或等距投影。Schema 校验通过和编译成功不能证明角色设计成立。

本次修订保留记录、版本安全和可证明检查，不再要求通过通用椭圆拼装器先完成角色设计。用户已同意：分清视觉设计与记录/检查，修复试点接线，再拿旧角色实际图片做受控视觉探索。旧 design-1c35be31a10d5b65 仅保留实验历史，不作已批准角色/风格/构图输入。

历史修订时核实的接线缺口（非当前未修复清单）：art-pilot 脚本插入本地源码路径；extract_acceptance 把 alpha-bounds 错降为 human；请求仍手填检查项及任意 prompt；identity.* 与编译包 identity 的命名不一致；旧 run_flow/review_check 尚未统一绑定 ProductionStore 的精确候选。仅改输出后缀不能保证不可覆盖；maliang.lock 的旧提交也不包含未提交新模块。这些问题须在真实生图前关闭。

用户已确认：

- 家族合同负责形体、风格、相机规则；单体 Draft 负责角色差异。
- 马良提供机制；art-pilot 提供项目数值、素材和美术决定；不迁移 tactics 管线。
- 确定性编译生成施工包，不保证随机图像服从几何。机器检查与人工艺术裁决分开。
- 无人类美术师也可从零探索；不要求预先提交 model sheet 或完整三视图。
- 一张人类认可的 DR Idle 图和身份特征清单构成最小角色定稿；认可的候选可直接采用，无需再生成。
- 生成、AI 编辑、外部手绘修改均可成为生产步骤。每个 view×state 是独立成像任务，不限定总调用次数；探索和正式采用的资格分开，所有调用和修改都保留来源。
- 形体身份固定，姿态投影可变。不能把动作一致性实现为所有二维包围盒相同。
- v1 支持 isometric：原生 DR/UL，镜像派生另两向；flat-2d 明确 unsupported。
- 包含跨视角一致性、Idle/攻击状态族、用户输入指引；组件分层、动画帧与图集延后。

## [S2] 合同、草案与用户输入

### 视觉设计与工具职责

- Agent/用户及图像后端负责视觉探索：看实际风格参考，提出形象候选，用户判断，按明确反馈编辑。不新增信条、人设、Boss 机制。
- 马良负责需求整理与执行准备：保留规则优先级、完整 prompt、已验证参考图职责、精确调用参数和验收清单；不声称编译器自动解决造型。
- 几何包负责已定义证据的量测与处理；人工判断物种、风格、姿态、威胁感。检查过不代表美术过。
- 不强迫用户填部件坐标、比例变体或先选占位图才能探索。先前未经用户认可的喙/翼/足椭圆坐标不作为硬设计约束。

### 家族合同

版本化 JSON 设计记录，独立于已有 YAML 状态策略。包含合同 ID、相机模式、支持的轮廓与附着结构、画法规则、色值规则、测量/审核策略及允许的状态变形。状态策略继续用 YAML；不将其兼作美术合同。

项目数值不写进通用库。122px 是 tactics 的完整轮廓尺寸参考，不是通用核心高度；236 是项目落点，不是所有资产的固定值。

### SpriteSliceDraft

保持七组：identity、topology、silhouetteClass、visualMoment、paletteRoles、targets、references。

- identity：物种、需识别的特征、识别优先级；不自动扩写世界观。
- topology：核心区域定义、附着部件、允许/禁止结构；区分固有身份与姿态变化。
- silhouetteClass：记录 capsule/ball 等形体意图；视觉生成能力与占位渲染能力分开声明。某形体不能被占位渲染器表达，不等于外部画师/图像模型不能探索它。现有渲染器仍只支持 capsule/ball 调试图。
- visualMoment：原生视图和状态任务列表，每任务声明动作时刻、变化范围；不凭 attack 标签自动设计攻击。
- paletteRoles：继承或声明主/辅/描边/强调色及硬约束、建议项。
- targets：源/输出尺寸、水平锚点、落点、显示尺寸、语境板参数和误差；不凭物种推断阈值。
- references：可为空；每图绑定相对路径、SHA-256、职责及允许借用/禁止借用内容。风格、身份、形体、姿态参考相互独立。同一图可承担明确列出的多项职责，不默认跨角色身份迁移。

初始用户输入只需：角色意图、家族风格、相机、状态范围、身份特征、显示语境。合同已知的数值自动继承，不能强迫用户手填合同 ID 或像素坐标。

工具列出缺失且会改变结果的决定，Agent 与用户收束后形成完整 Draft。未知字段不猜成已确认；自动/人工审核归属由能力表与合同生成。至少提供一条失败描述；无参考图时使用从零探索路径。

## [S3] 确定性执行准备与视觉能力边界

保留 authoring 的校验、规则整理、参考职责和请求准备功能；construction packet 的定位改为 execution/design brief packet，不把名字或 API 的成功返回当作视觉设计证明。修订时尚未提交的 API 现已随 0283eb9 入库；后续调整应以版本兼容性与实际用法为依据，不添加双权威格式。

执行包必含：完整可读 prompt、任务 view/state、图像输入顺序/职责/哈希、实际后端参数、继承后的输出/显示尺寸、全部必需自动/人工验收项及出处、语境板布局。相同语义输入生成稳定包；输入图列表的顺序有意义，不能随意排序。

几何占位图为可选 debug 产物，明确标记 debug-layout、unapproved、not-generation-input。默认不进入 imageInputs，不作为必需前置步骤，也不再称角色剪影探索。当前圆块和朝向三角仅展示代码布局，不能证明钩喙、双翼、双足、DR/UL 遮挡。旧产物保留，不删除、不覆盖、不用于 v03 身份/造型参考。

真实剪影/概念候选由受控图像生成或编辑提出，先展示给用户；不需要编译器造出几张椭圆供人硬选。首轮不必提供完整三视图；用户认可的 DR Idle 与身份清单直接成为定稿。

分开声明执行后端、图像参考输入、调试渲染和检查能力。无 debug 渲染不阻断视觉探索；必需的真实参考输入能力不支持时停止对应执行，不能退回文字却宣称参考图已经传入。必需自动检查未实现则保持 pending/unsupported 并阻止正式采用，不阻止诚实的探索候选生成。

本轮不实现 LoRA、通用绘画 DSL、复杂骨架或新的占位形体库；不继续以更复杂的椭圆拼装补视觉设计缺口。

## [S4] 调用、修改与定稿血缘

建议新增 production 包，复用 existing artifact/core/workflow primitives，但不改变已有 v1 记录字段语义。

- 调用前冻结完整请求：prompt、参数、输入图顺序/职责/哈希、设计包哈希、任务和 attempt ID。未知真实模型标识记录 unknown，不冒称 GPT 订阅。
- 调用成功绑定 delivery 和源图哈希；失败单独记录。每次调用有独立 attempt，编辑记录父源图与修改指令。
- 导入已有图采用 imported/historical 记录；禁止伪造过去 invocation、时间或完整 prompt。
- 原图、处理图、导引、审核记录不可覆盖；派生文件绑定源 attempt 与处理参数。
- asset 当前状态是可更新投影，不用不可变写入覆盖同一路径；更新使用原子替换。不可变事件用于核对投影。
- 人工认可绑定精确图像哈希、身份清单及实际用户决定。reviewer 只是监督开发者归属，无新增账号/CI 权限系统，也不能由 Agent 自称 dev 自动批准。
- DR Idle 定稿不强制二次生成。后续 UL/攻击引用定稿，参考改变后既有批准不自动延伸。
- 待审、否决和已采用分开；探索不是无日志区。过程与图片留在项目，不复制进马良公开 fixture。

图像工具实际调用由 Agent/项目适配完成；库提供 prepared request 与绑定结果的接口。导出请求和实际执行参数必须一致；只有记录接口不能证明输入图已进入服务。

## [S5] 核心、完整轮廓与落点测量

建议独立 geometry 包：measure、compare、transform、report。至少区分三份证据：

- 核心：用户确认的身体区域，不包含翼、尾、足、装备和效果；以同坐标二值蒙版绑定候选哈希。
- 完整轮廓：alpha 包围盒，用于裁切、安全边距和画布占用。
- 接地/虚拟落点：显式坐标或接触标记；不把最低非透明像素默认当脚底。

Agent 可提出核心蒙版，但提交审核板让用户确认；不得靠颜色猜分割后自动宣布身体一致。缺少核心证据时核心检查为 pending，不能用全图 bbox 补位。

输出核心高宽、中心、截面宽度、轮廓 bbox、落点及检查状态。对齐仅统一缩放和平移；源图/蒙版/接触点使用同一变换，保留原始测量与处理后结果。变换越界报错，禁止静默裁切、单轴拉伸或用缩放掩盖比例错误。

DR/UL 静立比较对应核心体量，容差由合同声明。姿态投影比较在声明坐标/变换下实施，倾斜或展翼不要求整图高宽相等；身份与遮挡不能完全自动量测的部分交人审。

色值指标只实现可证明的测试，不用统一颜色总数硬判风格。透明边缘的采样规则在合同里声明；主观画风裁决独立。

## [S6] 相机、状态族与审核

isometric 默认项目映射：North=UL、South=DR、East=UL+flipX、West=DR+flipX。屏幕 DR/UL 与逻辑方向分开记录；映射属于项目相机 profile，不扩展为所有等距游戏通则。

两张原生视图分别生成，镜像为确定性派生；不将镜像冒称原生背视。需项目显式接受镜像造成的装备换手。禁止镜像的身份标记或部件输出冲突诊断，不偷偷交换身份含义。

每个状态定义共享身份、允许的核心姿态变换及部件变化。库不自动补攻击表现；未指定代表时刻的任务保持待设计。

固定审核包：原始/处理后候选、核心蒙版、128/150 或项目指定尺寸预览、彩色/灰度、批准图并排、四向语境板、跨视角/状态差异报告。

技术结果与人审分别为 pass/fail/pending/unsupported。用例自动结果不能把“预览存在”当识别通过，旧版本人审不能附到新候选。采用操作核验当前候选与全部要求的证据绑定；未执行的人工项阻止采用。

## [S7] 实施阶段、验证与验收边界

本轮执行顺序：先修角色设计/调试图语义和试点接线，以合成素材完成真实端到端回归，再展示旧角色实际风格参考及明确职责，冻结请求后执行一次游隼 DR Idle 视觉探索，展示原图/小图/旧角色对照并等待用户判断。用户接受候选后再做蒙版确认、几何与技术检查、正式采用。UL/攻击列为后续验证，不在首轮同时扩展；攻击代表时刻由用户确认。

游隼首轮沿用已认可输入：真鸟拓扑、收翼、两足、短尾、钩喙、颊纹、DR 警觉静立；不复制犬脸、四爪、尾形或装备。旧胶囊角色图负责画法、核心形体语言和镜头参考，不负责游隼身份。不把笼统“真鸟拓扑”强制解释为写实比例，也不把未经认可的占位坐标解释为最终形体。

公开测试一律合成 PNG/JSON，不加入朋友游戏或 tactics 生产图。马良运行 pytest、build、CLI 黑盒、wheel 安装烟测；查询现有配置后执行其 lint/typecheck（若仓库未配置，明确缺口，不杜撰通过）。

art-pilot 在独立环境安装明确提交/构建产物，不依赖马良源码树隐式导入。端到端测试使用离线适配器验证顺序/版本/失败路径；真实生图和人工体验单独验证，离线成功不代替美术成功。

实现阶段完成验证后独立 review；修复后重验受影响区域。人工几何/艺术验收未过就不宣布角色交付。
